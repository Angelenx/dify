当前 .env 实测结论

本地化存储已确认

PostgreSQL、Redis、Weaviate、OpenDAL 文件存储和插件存储均指向 Compose 内服务或项目内目录，全量目录迁移方向正确。

8 个地址必须改新 IP

Console、Service、Trigger、WebApp、FILES_URL 及 INTERNAL_FILES_URL 当前均依赖旧外部 IP；漏改会永久依赖旧代理。

密钥必须原样迁移

SECRET_KEY 及数据库、Redis、Weaviate、Plugin、Sandbox 等认证值必须保持一致，不在迁移窗口轮换。

已确认的配置风险：docker/.env 当前权限为 777 且包含生产凭据；目标端恢复后应在确认 Compose 可读的前提下收紧到 600。当前还存在 HTTP、宽 CORS、Swagger 开启、Weaviate 匿名访问和插件签名校验关闭等安全基线问题，应在迁移稳定后单独整改，不与本次迁移混做。

数据迁移方法：主介质 + 双重兜底

主介质

完整项目 tar → 7z

源 Compose 完全停止后，对 /data/angelen/dify 完整归档。tar 保存 UID/GID、ACL、xattr 和软链接，7z 提供压缩。

兜底 1

PostgreSQL 逻辑备份

额外生成 pg_dumpall 和业务库/插件库 custom-format dump，在物理目录无法直接恢复时提供结构化恢复路径。

兜底 2

Weaviate 逻辑备份

使用已经启用的 filesystem backup，把向量集合以 Weaviate 支持的方式导出，防止仅复制底层文件后出现兼容问题。

归档链路

Stop停止全部 Compose 容器
Snapshot记录 Git、镜像、计数、Compose
tar保留 Linux 元数据
7z压缩并执行 7z t
SHA-256生成内容校验值
rsync支持断点续传
Restore校验通过才允许解压
tar --xattrs --acls --numeric-owner -cpf dify-full.tar dify
7z a -t7z -mx=3 -mmt=on dify-full.tar.7z dify-full.tar
7z t dify-full.tar.7z
sha256sum dify-full.tar.7z > dify-full.tar.7z.sha256
rsync -ah --partial --append-verify dify-full.tar.7z* root@NEW_IP:/data/migration/
禁止操作：不得执行 docker compose down -v，不得在迁移窗口清理 volume、镜像或源目录。

旧 IP 无感过渡方案

由于超过 50 台终端或开发者可能仍使用旧 IP，迁移后不立即释放源服务器。旧端停止所有 Dify 容器，仅部署独立 Nginx，将每个旧入口代理到新服务器相同端口。

Nginx 必须支持

  • HTTP/1.1 keepalive
  • SSE：关闭 proxy_buffering
  • WebSocket：传递 Upgrade/Connection
  • 大文件：提高 client_max_body_size
  • 长任务：提高 read/send timeout
  • 保留 X-Forwarded-For 和客户端 IP

停止转发条件

  • 所有智能体开发者确认改用新 IP
  • 旧 Nginx 日志无有效业务访问
  • 新端业务与技术验收稳定
  • 新端自动备份成功运行并抽检
  • 源端回滚点至少保留 30 天
多入口要求：当前访问形式包含多个 IP/端口。正式盘点必须形成完整映射表：旧 IP:旧端口 → 新 IP:相同端口，逐入口验证页面、API、SSE、WebSocket、上传和插件调试。HET 环境中的 INTERNAL_FILES_URL 必须指向插件可访问的新服务器外部 IP:端口，不能改为容器内 http://api:5001；否则外网插件无法下载文件。

验收闸门

容器显示 Up 不代表迁移成功。必须通过数据、功能、协议和定制四层验收。

基础设施

健康检查、数据库、Redis、Weaviate、Sandbox、插件、磁盘和队列。

数据完整性

账号、应用、工作流、知识库、文档、会话、向量对象、文件与插件计数。

业务链路

登录、聊天、工作流、知识库检索、上传下载、模型及插件调用。

HET 定制

App 权限、会话软删、HTTP 复制、变量块、Excel、SSRF 与匿名 share 页。

开放写入决策

GO：可以开放

  • 数据计数一致
  • 关键链路全部通过
  • 无持续错误和重启
  • 迁移负责人明确授权

NO-GO：立即停止

  • 数据库/向量/文件不一致
  • 登录、应用、工作流或知识库失败
  • 插件大面积失效
  • HET 关键定制回退

回滚决策树

发现严重故障停止新端流量与写入
是否已开放写入？判断增量数据窗口
否直接停新端，启动旧 Compose
是归档新端现场，接受增量丢失
恢复旧端停止 Nginx，启动源 Compose

开放写入前

源端从停机后没有任何数据变化。停新端、停代理、启动源 Compose 即可，属于低风险回滚。

开放写入后

已确认可接受新端增量数据丢失。回滚前仍应停止新端并保存现场，明确通知业务方丢失时间窗口。
